# Database Architecture & Migration Guide

This directory contains the database design and migrations for the University Timetable Management and Clash Detection System.

## Architecture

The system supports two complementary database modes:

1. **Embedded Node.js SQLite (`database/timetable.sqlite`)**:
   - Zero-external-dependency, production-ready local database powered by Node.js 26's built-in `node:sqlite`.
   - Requires no PostgreSQL or Supabase installation to run the complete portal, backend, and C++ engine locally.
   - Automatically migrates, seeds, and provisions administrator accounts on initial boot.

2. **Supabase / PostgreSQL (`database/schema.sql`)**:
   - For cloud or distributed deployments with Supabase Auth and Row Level Security (RLS).
   - Use `database/migrations/001_initial_schema.sql` and `database/migrations/002_views_and_policies.sql`.

## Schema Entities

- `admin_profiles`: Provisioned administrators from `admin_master.csv`. Passwords securely hashed with `scrypt` and salt.
- `students`: Student directory with ID, name, section, group, and status.
- `faculty`: Faculty master directory loaded from `faculty_master.csv`. Stable IDs `F001`-`F075`.
- `departments`: Academic departments.
- `programmes`: Academic degree programmes.
- `academic_years`: Active and historical academic years.
- `semesters`: Semesters (e.g., 3rd Semester, Autumn 2026).
- `subjects`: University course subjects, codes, and credits.
- `sections`: Student cohort sections (`A`-`K`, `AI-DS1`, `AI-DS2`, `AI-ML1`-`AI-ML4`, `Cyber`).
- `student_groups`: Lab groups (e.g., G1, G2).
- `rooms`: Lecture theatres (`LT-*`), classrooms (`CR-*`), labs (`Digital Lab-*`, `Lab-*`), and auditorium (`GEHU-Audi`) with capacities.
- `timetable_sessions`: Scheduled lecture and lab sessions with draft/published state.
- `timetable_versions`: Version history records for published timetables.
- `timetable_imports`: Audit log of CSV imports.
- `clash_runs`: Audit trail of C++ clash detection executions.
- `detected_clashes`: Identified clashes categorized by type, severity, and affected sessions.
- `resolution_proposals`: Suggested resolutions generated by the C++ resolver.
- `resolution_actions`: Audit trail of administrative resolution approvals and rejections.
- `audit_logs`: Central administrative audit trail.
- `system_settings`: Configuration key-value store.
